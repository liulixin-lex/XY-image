## v0.0.18（2026-10-18，Claude Code）

**结论：参考图上传前先在浏览器里压缩，上传有真实进度，上传中点发送会在传完后自动发出；设计助手出的图放在当前视野附近，落在屏幕外时自动移过去，「已放到画布」只在本地画布确实有这张图时才显示。没有数据库迁移，`server.env` 和代理配置都不用改。** 版本标签 `v0.0.18`（GitHub Release），各包版本号同为 0.0.18，`GET /api/health` 返回的 `version` 也是它。用户 10-18 反馈：「上传图片时很慢」「生成图片后提示已在画布上，但画布里没看到」「上传时没有动态提示，像卡住了，传完之前不能点发送」。

### 问题和原因（正式站只读排查，10-18）

| 问题 | 原因 |
| --- | --- |
| 上传慢 | 慢在用户网络：访问日志里部分用户上传只有 50–300 KB/s，1.6 MB 的图要 8–37 秒，还有 3 次中途放弃；25 KB 的图服务端全程 60 ms。0.0.17 只压缩超过 8 MB 的图，3–6 MB 的手机照片原样上传 |
| 提示已放到画布，却看不到 | 服务端把助手的图一律放在「最右侧元素的右边 40 px」，前端合并后不移动视野。画布 `01934d03`（10-17 19:24–19:41）9 张图都写进了画布，浏览器也都拉到了，但落在 x = 1620 … 5712，一字排开在屏幕外。新项目的第一张图能看到，是因为 React Flow 对空画布的 fitView 会等到第一批节点出现，所以「时好时坏」。另外生图后的 `canvas.sync` 不进重连补发缓冲，页面恰好在重连时会补发「已放到画布」的卡片却不补发同步，图要刷新才出现 |
| 上传像卡住 | 上传用 fetch，拿不到进度；整个过程只有缩略图上一个 8 px 的呼吸点和一行灰色小字；发送按钮只是变灰，回车没有任何反应 |

### 改动（PR #108）

| 方面 | 内容 |
| --- | --- |
| 压缩 | 512 KB 以内、或 2048 px 以内且 1.5 MB 以内的图原样上传；其余缩到长边 2048（照片 JPEG q0.88，透明图保留 PNG），超过 8 MB 再缩到 1536、1024；压缩省不到 20% 就传原图。服务器发给模型前本来最多也只送 2048 px 的细节，遮罩由服务端按原图缩放，效果不变。浏览器支持 OffscreenCanvas 时在 Web Worker 里压缩，不卡页面；不支持或 worker 读不了的图在页面里压缩 |
| 上传 | 改用 XMLHttpRequest 拿真实进度；同时最多传 2 张；移除图片立刻中断上传；30 秒没有进展判为失败，可以重试 |
| 上传提示 | 缩略图：压缩中（扫光）→ 进度环和百分比 → 打勾。图片下方写「图片上传中 62%」。首页、生图页、对话框里，上传中点发送 / 生成（或按回车）会变成「传完自动发送」，传完自动发出，再点一次取消；有图失败时按发送，原因会晃一下 |
| 画布落点 | 发消息时带上当前视野（`canvasView`，可选字段），生图任务记下视野中心（`canvas_near`），worker 把图放在中心附近的空位，不压在已有元素上。旧页面不发视野，图按原来的方式放 |
| 画布视野 | 助手的新图落在屏幕外时，视野平滑移过去，新图短暂高亮；用户正在拖动或滚动画布时改为弹出「新图片已放到画布 · 查看」。生成节点自己的图只高亮，不移动视野 |
| 对话卡片 | 「已放到画布」只在本地画布确实有这张图时显示，之前显示「正在放到画布…」，并提供「在画布中查看」（手机上先收起对话面板） |
| 画布同步 | 生图放好后的同步改为走运行事件流，重连会补发；页面重连、回到前台时各补同步一次；同步失败 2/5/15 秒后重试；工具说放好了而本地 2.5 / 8 秒后还没有，会再拉一次 |
| 同类问题 | 拖进画布的图先压到 4 MB 以内（以前 10 MB 原图以 base64 塞进保存请求，两张就超过 20 MB 上限）；生成节点用未保存的画布图做参考图时先压缩，扩展名按真实类型；服务端没放成功、由页面兜底插入的生成图也先压缩 |
| 日志 | 上传日志记录 `receiveMs`（网络）、`storeMs`（存储）、浏览器上报的原始大小和压缩耗时；画布落点日志记录落点和依据（slot / near / right-of-all） |

## v0.0.17（2026-10-17，Claude Code）

**结论：修好「生图模式传不了参考图」「对话助手传不了参考图」「首页带图发起对话时图片没和提示词一起发出去」三个问题；画布上还没保存的图片改为在页面里解码、不再走 fetch，为强制执行 CSP 做准备。没有数据库迁移，`server.env` 和代理配置都不用改。** 版本标签 `v0.0.17`（GitHub Release），各包版本号同为 0.0.17，`GET /api/health` 返回的 `version` 也是它。用户 10-17 反馈：「生图模式无法上传参考图；对话助手无法上传参考图；对话模式上传参考图后，无法与请求提示词一同发出去」。

### 问题和原因（正式站只读排查，10-16/17）

| 问题 | 原因 |
| --- | --- |
| 生图、对话传不了参考图 | 页面和接口都只收 10 MB 以内的图。超过的图在页面上只用悬停提示说明，「重试」又不检查大小直接上传，接口把超限当成 500 返回，界面一直显示「上传失败，点击重试」。48 次上传里有 17 次是 12–19 MB 的图（手机照片、本站自己出的 4K 图），全部返回 500 |
| 从首页带图发起，图没发出去 | 新画布自动发送首条消息时，先从 sessionStorage 取出图片并清掉，再延时发送。实时连接晚于会话建好时，连接引起的重渲染必定取消这次发送，再进来已经取不到图，只发出了文字。10-16 有 3 次都是这样 |
| 对话里上传失败的图被悄悄丢掉 | 对话框发送时不检查有没有上传失败的图，文字照常发出 |

### 改动

| 方面 | 内容 |
| --- | --- |
| 参考图压缩（PR #104） | 超过 8 MB 的图在浏览器里按服务器发给模型前的同一标准压缩（长边 3072 px，不够再到 2048 px；照片转 JPEG q90，透明图保留 PNG），模型看到的效果不变，上传量小很多。8 MB 以内原样上传。没标类型的文件按文件头识别；拖入或粘贴的 HEIC 图片在 Safari 里自动转换，其他浏览器会提示先导出成 JPEG 或 PNG |
| 上传失败的提示（PR #104） | 首次上传和重试走同一条路，重试不能再绕过检查。太大、格式不对这类重试也不会成功的失败，不再显示「重试」，原因写在图片下方并弹出提示。图片还在上传或上传失败时，对话框、首页、生图页都不让发送，并说明原因 |
| 上传接口（PR #104） | 上限 19 MiB（低于代理的 20 MB，代理不用改）。超限返回 413 `file_too_large` 和中文原因，其他上传错误返回 4xx，不再变成 500。每次只收一个文件。上传的成功和失败都记日志（含大小） |
| 首页带图（PR #104） | 首条消息的图片、生图偏好、对话模型在真正发出的同一时刻才读取，不会再因为重渲染丢失 |
| CSP 准备（PR #105） | 画布上还没存进 Storage 的图片是 data: 地址。生成节点拿它当参考图、画布和对话里下载图片时，原来都用 fetch 读取，被 `connect-src 'self'` 上报过。现在在页面里解码，不发请求；对话大图和图片卡片的下载也改用同一个下载函数。CSP 策略不用改 |
