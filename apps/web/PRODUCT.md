## Platform

web

## Users

- **主站现有用户（推断，主要）**：已在 xy2api 主站注册、充值美元余额、持有 API Key 的用户。他们熟悉「Key、分组、余额、用量」这些概念，想要一个不写代码就能出图、改图、做设计稿的可视化工作台。
- **新创作者（推断，次要）**：设计师、电商运营、自媒体等非技术用户。他们需要先去主站注册并充值，再回到生图站登录使用；生图站要把这条路径讲清楚。
- 使用场景：桌面浏览器为主（无限画布、对话侧栏），移动端可以浏览、查看结果和做简单生成。

## Product Purpose

GGUU AI IMAGE 是 xy2api 主站的生图站。用户用主站的同一套账号密码（含 TOTP 二次验证）登录，生图和 Agent 对话都直接使用自己在主站的 API Key，费用从主站美元余额中扣除。生图站不设自己的积分、套餐或支付。

成功标准：
- 主站用户登录后几分钟内产出第一张图；
- 每一次扣费都能在主站用量页核对上；
- 余额、Key、模型出问题时，用户清楚知道该去哪里处理。

## Positioning

和主站共用一本账：同一账号、同一余额、同一批 Key，按主站分组价格计费，没有二次加价，也没有第二套积分。
在此之上提供两种创作方式：
- **直接生图**：一句提示词加参数，立刻出图；
- **画布 + 设计 Agent**：在无限画布上和 Agent 对话，让它规划并连续出图、排版。

## Operating Context

- 登录：主站邮箱 + 密码，可能需要 TOTP 6 位验证码和 Cloudflare Turnstile；注册、找回密码、充值、Key 管理、用量明细都跳转到主站完成。
- 生图之前，用户在「设置」里选择一个能生图的 Key；能用哪些模型由这个 Key 所在的分组决定。
- 计费只发生在主站；生图站每个任务都会记录计费状态（已扣费 / 未扣费 / 待核对）和主站请求 ID。
- 生成可能耗时 1~10 分钟（ChatGPT 账号池上游较慢），而且请求一旦发出就不会自动重发。

## Capabilities and Constraints

- 模型以主站 Key 实际可用的为准，默认目录 7 个：GPT Image 2、GPT Image 2.5 Sunburst / Flare、Nano Banana 2.1 / Pro / 2（Gemini）、Grok Imagine 2.0（目录在 `apps/server/src/features/xy2api/catalog.ts`）。
- 画质 1K / 2K / 4K（输出尺寸档位，主站按档计价），质量 自动 / 低 / 中 / 高，各模型能选的不同；没有视频。
- 比例最多 10 种（1:1、3:4、4:3、9:16、16:9、2:3、3:2、4:5、5:4、21:9），各模型可用的子集不同。参考图支持 PNG / JPEG / WebP，单张不超过 10 MiB，张数上限由模型决定（Grok 暂不支持参考图）。
- 一次最多 4 张，每张单独请求；每个用户同时最多发出 2 张、最多 8 张在排队或生成中，还没发出的可以取消。每轮 Agent 对话最多生图 6 次。
- 单张预估价（P1）、一键创建 Key（P1）、主站嵌入登录（P1）都未实现，不能展示。
- 技术栈：Next.js 15 静态导出（output: export）、React 19、Tailwind v4、React Flow 12 节点画布、Supabase 会话。浏览器只保存 Supabase 会话，不能出现主站 Key 或 JWT。

- 视觉方向「海报 · 柔和版」（F2，强调色珊瑚，亮暗两套主题；2026-10-10 替换「夜色光场」）：彩色、有空间感、交互丰富；不用琥珀/黄色铺色，不做纯黑白或刺眼的硬边海报。
- 文案直白亲切、有风格但不另类；不用暗房、冲印、显影这类行话。
- 中文优先。

## Product Principles

1. **账本透明**：只要涉及扣费，就要说清楚扣了没有、扣在哪里、去哪里核对；不能把未知说成没扣费。
2. **不替用户重发**：生成一旦提交就交给用户判断，界面不自动重试，也不因页面刷新而重发。
3. **主站是唯一真相**：余额、Key、模型、价格以主站为准，生图站只负责展示和引导，不自行推算价格。
4. **出图优先**：从任何入口到第一张图，步骤尽量少；画布和 Agent 是进阶能力，不是门槛。

## Accessibility & Inclusion

没有专项要求；按 WCAG 2.2 AA 执行，键盘可达，尊重 prefers-reduced-motion 设置。
